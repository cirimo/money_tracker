# Build files

How the build is organised and why is in
[docs/decisions/0002](../../docs/decisions/0002-gradle-build-structure.md). The current versions
and their compatibility caveats are in
[docs/decisions/0003](../../docs/decisions/0003-toolchain-versions.md). Read both before a
non-trivial build change.

## Where things go

- Every version and every dependency coordinate goes in `gradle/libs.versions.toml`. A version
  string in a build script or a convention plugin is a mistake, because the next upgrade will
  miss it.
- Configuration shared by modules goes in a convention plugin under
  `build-logic/convention/src/main/kotlin`. A module's `build.gradle.kts` holds only what is
  unique to that module: its namespace, its own dependencies, and for `:app` the application
  id, version and signing.
- Convention plugins cannot use the generated `libs.foo.bar` accessors. Use
  `libs.version("alias")` and `libs.library("alias")` from `VersionCatalog.kt`, with the alias
  exactly as written in the catalog.
- A new plugin class must be registered in `build-logic/convention/build.gradle.kts`.

## Dependencies and versions

- Ask the owner before adding a dependency or changing any version. Say what it is for, what
  the alternatives are and what it costs in size and maintenance.
- Never write a version number from memory. Look it up at the source (Google's Maven
  repository, Maven Central, the Gradle versions service) and check compatibility with the
  rest of the toolchain. Your recollection of version numbers is older than the releases.
- Use stable releases only. No alpha, beta, RC or snapshot versions without the owner's
  explicit agreement.
- Compose libraries take their version from the BOM, so they have no version in the catalog.
- Whether a library belongs in the project at all is often an architecture question. Check
  [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) first.
- After any change here, run `.\gradlew.bat check assembleDebug assembleRelease`, because a
  build change can break the release variant while debug still works.

## Things that are easy to get wrong here

- AGP 9 has Kotlin built in. Do not apply `org.jetbrains.kotlin.android`; it conflicts.
  Kotlin compiler options are set through `KotlinCompilationTask`, as in
  `AndroidApplicationConventionPlugin`.
- The configuration cache is on. Do not read files, environment variables or system properties
  at configuration time in ways that bypass Gradle's providers, and do not capture `Project`
  inside task actions.
- Spotless targets are file trees with excludes. A plain `**/*.kt` glob at the root walks into
  `.gradle` and `build` and fails on locked files on Windows.
- Lint treats warnings as errors and has no baseline. Do not add a baseline or disable a check
  to get a build through; see [docs/decisions/0010](../../docs/decisions/0010-quality-tooling.md).
- `local.properties` and `keystore.properties` are untracked and must stay that way. The
  release signing block must keep working when `keystore.properties` is absent, because CI and
  fresh clones depend on that.
- Upgrade the wrapper with `.\gradlew.bat wrapper --gradle-version <v> --gradle-distribution-sha256-sum <sum>`
  and run it twice, so the wrapper scripts and jar are regenerated by the new version. Take the
  checksum from `https://services.gradle.org/distributions/gradle-<v>-bin.zip.sha256`.
